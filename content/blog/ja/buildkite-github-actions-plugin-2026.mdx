## GitHub Actionsのワークフローがそのまま動く

2026年8月17日、BuildkiteはGitHub Actions OSS Pluginをパブリックプレビューとして公開しました。既存の `.github/workflows/*.yml` に書かれたGitHub Actionsのワークフローを、書き換えることなくBuildkiteのパイプライン上で実行できる仕組みです。互換性のあるワークフローをそのまま動かし、準備が整った段階でBuildkiteネイティブのパイプラインへ段階的に移行できます。

Webhaniでは複数のクライアント案件でCI/CD基盤の選定・移行を支援しており、この種の「移行コストを下げる橋渡し機能」は実務上の関心が高いトピックです。

## なぜこれが問題を解決するのか

CI/CD基盤を乗り換える際、最大の障壁は「動いているワークフローをゼロから書き直すコスト」です。GitHub Actionsで数十から数百のワークフローファイルを運用しているプロジェクトを、別の基盤へ移行しようとすると、構文の違いだけでなく、Actionsのマーケットプレイスに依存した処理の置き換えが必要になり、移行プロジェクトそのものが数週間から数ヶ月かかることも珍しくありません。

Buildkiteのアプローチは、この「書き換え」を後回しにできる点が特徴です。

```yaml
# Buildkite pipeline.yml (イメージ)
steps:
  - label: "Run existing GitHub Actions workflow"
    plugins:
      - github-actions#v1.0.0:
          workflow: ".github/workflows/ci.yml"
          job: "test"
```

まずは既存のワークフローをそのままBuildkite上で動かして基盤を切り替え、その後に必要な部分からBuildkiteネイティブなステップへ書き換えていく、という段階的な移行が可能になります。

## CI/CD基盤選定でロックインを避ける視点

Webhaniがクライアントに提案する際は、CI/CD基盤そのものの機能比較だけでなく、「乗り換えるコスト」を事前に見積もることを重視しています。

- **ワークフロー資産の可搬性**: GitHub Actions固有の構文やマーケットプレイスのActionsに強く依存したワークフローほど、他基盤への移行コストが高くなる
- **段階的移行の余地**: 一括移行ではなく、リポジトリ単位・ワークフロー単位で段階的に移行できる仕組みがあるかどうか
- **並行運用期間の設計**: 移行期間中、旧基盤と新基盤を並行稼働させる場合のコスト増をあらかじめ見込んでおく

BuildkiteのGitHub Actions Pluginは、まさに2つ目と3つ目の観点に直接効いてくる機能です。互換レイヤーを挟むことで、移行の意思決定と実際の書き換え作業を分離できます。

## 実務での検討ポイント

Webhaniでは、この種の互換レイヤーを導入する際に次の点を確認することを推奨しています。

1. **互換性の範囲を早期に把握する**: すべてのGitHub Actions構文やマーケットプレイスActionsが完全互換とは限らないため、実際に使っているワークフローで動作検証を行う
2. **パフォーマンス特性の違いを計測する**: 同じワークフローでも実行基盤が変われば、キャッシュの効き方やジョブの並列度が変わり、実行時間に差が出ることがある
3. **移行のゴールを明確にする**: 「互換レイヤーで動かし続ける」ことをゴールにするのか、「最終的にネイティブなパイプラインへ完全移行する」ことをゴールにするのかを、プロジェクトの初期段階で合意しておく

## GitHub Actionsの料金動向との関係

同時期、GitHub ActionsのLinux標準ランナーの料金がCircleCIと同水準の1分あたり0.006ドルに揃ったという報道もあります。CI/CD市場全体で料金の差が縮まりつつある中、基盤選定の判断軸は「価格」から「移行のしやすさ」や「既存エコシステムとの統合度」へと重心が移りつつあるように見えます。Buildkiteのような互換レイヤーの登場は、この流れを象徴する動きと言えます。

## まとめ

BuildkiteのGitHub Actions OSS Pluginは、CI/CD基盤の乗り換えを「全部書き直すか、それとも動かないままにするか」の二択から解放する機能です。互換レイヤーを挟むことで移行の初速を上げつつ、必要な部分から段階的にネイティブな仕組みへ移行できる設計は、複数のクライアント環境でCI/CD基盤の選定を支援するWebhaniにとっても参考になる考え方です。CI/CD基盤を検討する際は、単純な機能比較だけでなく、こうした「乗り換えやすさ」も評価軸に加えることを推奨します。
