2026年8月14日、AnthropicはClaude CodeのPro/Max/Teamプランにおいて、新規セッションの既定パーミッションモードをAuto Modeに切り替えました。Auto Modeは2026年3月にリサーチプレビューとして登場した機能ですが、約5か月で「オプトインの実験機能」から「多くの開発者が最初に触れる標準挙動」へと位置づけが変わったことになります。

同じタイミングで、Background Job(worktree上でコードを変更するバックグラウンドセッション)がタスク完了時に自動でcommit・pushを行い、必要な場合のみDraft PRを開く挙動が導入されました。加えて、権限チェックを回避する手口を塞ぐセキュリティ修正も同時に入っています。単なる機能追加ではなく、AIエージェントに委ねる操作範囲そのものが広がったリリースだと捉えるべきです。

## 何が変わったか

今回のアップデートの要点は3つです。

1. **既定パーミッションの変更**: 新規セッションでは「都度確認」ではなく「Auto Mode」がデフォルトになった
2. **Background JobのGit自動化**: worktree上での変更をコミット・pushし、タスクの性質に応じてDraft PRを自動作成する。その際、プロジェクトの`CLAUDE.md`に書かれたgit運用ルールに従う
3. **権限チェックの強化**: Bashコマンドの一部をタブや不可視Unicode文字でパディングし、承認ダイアログから隠す手口が使えなくなった

3点目は地味に見えますが重要です。これまでは、コマンド文字列に見えない文字を混ぜることで、実際に実行される内容と承認ダイアログに表示される内容を乖離させる余地がありました。Auto Modeの適用範囲が広がるタイミングでこの穴を塞いだのは理にかなっています。

## なぜ実務上重要なのか

Auto Modeが既定になったことで、開発チームは「AIに何をどこまで任せるか」を明示的に設計する責任を負うことになります。これまで確認ダイアログが暗黙のガードレールとして機能していたチームでは、その前提が崩れます。

特に注意すべきはBackground Jobのgit自動化です。バックグラウンドで走るセッションが、人の目を通さずにcommit・pushまで到達しうるということは、`CLAUDE.md`に書かれたgit運用ルールが実質的に「実行される権限ポリシー」になったことを意味します。曖昧な記述や古い運用ルールを放置していると、意図しないコミットメッセージ規約違反やブランチ運用の逸脱が発生する可能性があります。

## CLAUDE.mdをポリシードキュメントとして扱う

これまで`CLAUDE.md`はガイドライン程度の位置づけだったチームも多いはずですが、Auto Mode既定化以降は、実際にエージェントの挙動を規定する設定ファイルとして扱うべきです。最低限、以下を明文化することを推奨します。

```markdown
## Git運用ルール

- コミットは常に新規コミットを作成し、既存コミットのamendは行わない
- masterへの直接pushは禁止。必ずfeatureブランチを作成する
- 破壊的操作(force push、reset --hard、ブランチ削除)は必ずユーザー確認を取る
- Draft PRのタイトルは `[auto] {変更内容の要約}` の形式に統一する
```

あわせて、`settings.json`側のパーミッション設定も見直しておくと安全です。

```json
{
  "permissions": {
    "allow": ["Edit", "Read", "Bash(npm run *)", "Bash(git status)"],
    "deny": ["Bash(rm -rf *)", "Bash(git push --force*)"]
  }
}
```

Auto Modeは「安全に実行できると判断したアクション」を自動で進める機能であり、何でも無条件に許可するわけではありません。ただし、その判断基準はチームが明示したルールとAnthropic側のデフォルト挙動の組み合わせで決まるため、`allow`/`deny`の設定を空のまま運用するのはリスクが高い、という点は変わりません。

## webhaniの推奨

1. **段階的ロールアウト**: チーム全体で一斉にAuto Modeへ移行するのではなく、まず個人の検証環境や低リスクなリポジトリで挙動を確認する
2. **Draft PRも通常のPRと同様にレビューする**: 自動生成されたPRだからといってレビューを省略しない。むしろ「なぜこの変更が必要と判断されたか」を確認する習慣を作る
3. **`CLAUDE.md`を定期的に棚卸しする**: 古い記述や曖昧な指示が残っていないか、四半期に一度は見直す
4. **セキュリティ修正の適用状況を確認する**: Claude Codeのバージョンが権限チェック強化を含む最新版になっているか、CIやローカル環境で確認する

Auto Modeの既定化は、AIコーディングアシスタントが「提案する」段階から「実行する」段階へ本格的に移行しつつあることを示す一つの節目です。webhaniでは、クライアント企業のAI活用支援において、こうした権限モデルの変化を前提としたCLAUDE.md設計やパーミッションポリシーの策定を継続的に支援しています。
