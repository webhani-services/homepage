## 地味だが効く変更

2026年9月、Claude Codeに2つの運用系アップデートが入りました。ひとつはセッション内で問題が起きた際にフィードバックレポートを下書きできる`SendFeedback`ツール、もうひとつはコマンド実行やバックグラウンドタスクの出力をモデルにインラインで渡せる上限を最大128Kキャラクタまで引き上げる`bashOutputMaxChars` / `taskOutputMaxChars`設定です。

派手な新機能ではありません。しかし、エージェント型コーディングを日常業務に組み込んでいるチームにとっては、地味な改善ほど効いてきます。本稿ではWebhaniの視点で、この2つの変更が実務に何をもたらすかを整理します。

## SendFeedbackツールが解決する問題

これまで、Claude Codeのセッション中に「これは想定外の挙動だ」と感じても、報告の手段は限られていました。スクリーンショットを撮る、ログをコピーして別途Issueを立てる、といった手作業が必要でした。

`SendFeedback`は、セッション内で問題を検知した際にClaude自身がフィードバックレポートの下書きを作成し、ユーザーが内容を確認してから`/feedback`経由で送信できる仕組みです。

```text
セッション中に予期しない挙動を検知
        ↓
Claudeがフィードバック下書きを生成
  - 何が起きたか
  - 期待していた挙動
  - 関連するセッションコンテキスト
        ↓
ユーザーが内容を確認・編集
        ↓
/feedback で送信
```

ポイントは「下書きはClaudeが作るが、送信の判断は人間が行う」という設計です。エージェントに自律性を持たせつつ、外部への報告という不可逆に近い操作には人間の承認を挟む。この設計思想は、Webhaniが顧客のAIコーディング運用を設計する際にも一貫して勧めているパターンと一致します。

## 出力上限の拡大が意味すること

もう一つの変更は地味ながら実務的です。これまでコマンド実行結果やバックグラウンドタスクの出力は、一定の文字数を超えるとファイルに退避され、モデルには要約や一部しか渡されませんでした。`bashOutputMaxChars`と`taskOutputMaxChars`の上限が128Kまで引き上げられたことで、より長いログやテスト出力をそのままモデルの文脈に載せられるようになります。

たとえば、大規模なテストスイートの失敗ログや、依存関係解決時の詳細な出力を扱う場面を考えてみます。

```bash
# 例: テストスイートの失敗ログが長大なケース
npm test 2>&1 | tee test-output.log
# 以前: 出力が切り詰められ、Claudeは要約情報しか見られない
# 現在: 128Kまでインラインで渡せるため、詳細な失敗箇所を直接参照できる
```

これにより、Claudeが「ログの一部しか見えていないために誤った推測をする」というケースを減らせます。デバッグの精度は、モデルがどれだけ「生の情報」にアクセスできるかに直結するため、この上限拡大は地味ながら診断品質に直結する改善です。

## 実務での使いどころ

Webhaniが顧客プロジェクトでClaude Codeを運用する際、この2つの変更が効く場面は次の通りです。

- **障害調査の初動**: CI失敗やビルドエラーの詳細ログをそのまま渡せるため、要約による情報欠落を心配せずに調査を依頼できます。
- **フィードバックループの制度化**: `SendFeedback`により、現場のエンジニアが「Claudeの挙動がおかしい」と感じた瞬間に、負担の少ない形で報告を残せます。属人的な口頭報告に頼らず、改善のための一次情報が蓄積されていきます。
- **大規模モノレポでのタスク実行**: 複数パッケージにまたがるビルドやテストの出力は長くなりがちです。上限拡大により、要約に頼らず実際の出力を踏まえた判断がしやすくなります。

## 運用上の注意点

出力上限の拡大は、モデルへの入力トークン量の増加を意味します。コストとレイテンシへの影響は無視できません。Webhaniでは、長大な出力をそのまま渡す設定は「デバッグや障害調査など、精度が優先される場面」に限定し、通常の開発フローではデフォルトの上限を維持することを推奨しています。すべてを最大値に設定するのではなく、用途に応じて使い分ける運用が現実的です。

また`SendFeedback`についても、下書きの内容をレビューせずに反射的に送信する運用は避けるべきです。フィードバックの質はチームの改善サイクルの質に直結するため、送信前のひと手間を省略しないことが重要です。

## まとめ

Claude Codeの2026年9月アップデートは、新機能の追加というより「エージェント運用の可観測性」を高める改善です。SendFeedbackは問題報告のハードルを下げ、出力上限の拡大は診断の精度を上げます。どちらも、エージェント型コーディングを本番運用に乗せる際に必要になる「地味だが不可欠な」インフラ整備と言えます。Webhaniでは、こうした運用面の改善を継続的に追いながら、顧客のAIコーディング導入を支援していきます。
