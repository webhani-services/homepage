## Next.js 16.3が届いた

2026年8月3日、Next.js 16.3がリリースされました。今回の中心はランタイム機能の追加ではなく、開発体験とビルド速度の底上げです。Webhaniでは自社サイトを含む複数のプロジェクトでNext.js 16系を運用しているため、実務目線でどこが変わったのかを整理します。

公式ブログによると、主な変更点は以下の4つです。

- 長時間の開発セッションでのメモリ使用量を最大90%削減
- 負荷時に処理できるリクエスト数を最大22%改善
- リピートビルドで変更のないアーティファクトをキャッシュから読み込み
- `next build` の型チェックにTypeScript 7を利用可能に

## なぜ開発時メモリが90%も減るのか

Next.jsの開発サーバーは、ファイル変更を検知するたびにモジュールグラフやコンパイル結果をメモリ上に保持し続けます。プロジェクトが大きくなるほど、また開発セッションが長くなるほど、このキャッシュが肥大化していくのが従来の課題でした。

16.3ではTurbopackにメモリエビクション(不要になったキャッシュエントリを能動的に破棄する仕組み)が実装され、永続ビルドキャッシュと組み合わせることで、メモリ上に保持する範囲を必要最小限に絞り込めるようになりました。開発機のメモリを丸一日かけて食いつぶし、最終的にVS Codeごと固まる、というよくある症状に直接効いてくる変更です。

```bash
# 開発サーバーのメモリ使用量を簡易的に確認する
npm run dev &
DEV_PID=$!
sleep 60
ps -o rss= -p $DEV_PID | awk '{printf "RSS: %.1f MB\n", $1/1024}'
```

大規模なモノレポや、コンポーネント数が数百を超えるようなプロジェクトほど恩恵を受けやすいはずです。Webhaniで運用しているクライアント案件のいくつかは、まさにこの規模感に該当します。

## リピートビルドのキャッシュ活用

CI環境で `next build` を繰り返し実行する際、変更のないファイルに対応するビルド成果物をディスクキャッシュから読み込めるようになりました。GitHub ActionsなどでNext.jsのビルドキャッシュをジョブ間で永続化している場合、この恩恵はそのまま効いてきます。

```yaml
# .github/workflows/build.yml (抜粋)
- name: Restore Next.js cache
  uses: actions/cache@v4
  with:
    path: .next/cache
    key: nextjs-${{ hashFiles('package-lock.json') }}-${{ github.sha }}
    restore-keys: |
      nextjs-${{ hashFiles('package-lock.json') }}-
```

キャッシュキーの設計自体は従来から変わりませんが、キャッシュヒット時に読み込まれるアーティファクトの範囲が広がったぶん、CIのビルド時間短縮効果は大きくなります。

## TypeScript 7による型チェック

`next build` の型チェック工程でTypeScript 7を選択できるようになりました。TypeScript 7はコンパイラのコア部分がネイティブ実装に置き換えられており、大規模プロジェクトほど型チェック速度の改善が体感しやすいとされています。既存のtsconfig設定をそのまま使えるため、切り替えのハードルは低めです。

```json
// next.config.mjs での有効化イメージ
const nextConfig = {
  typescript: {
    tsc: "typescript-go", // TypeScript 7ベースの型チェッカーを利用
  },
};
```

導入初期は型エラーの検出パターンに差異が出るケースがあるため、Webhaniでは本番CIにいきなり切り替えるのではなく、ローカル開発とプルリクエストのドラフトビルドで先行検証することを勧めています。

## 実務での対応方針

Next.js 16系をすでに利用しているプロジェクトであれば、16.3へのアップデートはマイナーバージョンの範囲内で完結します。破壊的変更は報告されていないため、通常のパッケージ更新フローで問題ありません。

- 開発サーバーのメモリ使用量に日々の作業でストレスを感じているチームは、優先度を上げてアップデートする価値があります
- CIのビルド時間がボトルネックになっている場合は、キャッシュ設定を見直すタイミングとしても良い機会です
- TypeScript 7への切り替えは、まずローカル環境で型エラーの差分を確認してから展開するのが安全です

## まとめ

Next.js 16.3は、機能追加よりも「毎日の開発を軽くする」ことに振り切ったリリースです。派手さはありませんが、開発機のメモリ逼迫やCIの待ち時間といった、地味に生産性を削る要因への対処として着実に効いてきます。Webhaniでは今後もフレームワークのマイナーアップデートを継続的に検証し、クライアントプロジェクトへの適用可否を判断していきます。
