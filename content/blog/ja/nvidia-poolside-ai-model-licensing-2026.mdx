2026年8月下旬、NvidiaはAI Startup企業Poolsideの「Model Factory」——Coding特化のGenerative Modelを生成するためのPlatform——を60億ドルで非独占ライセンスし、加えて評価額120億ドルでPoolsideに10億ドルを出資しました。Poolsideの創業者はこれがAcquisitionではないと明言しており、会社は独立を保ち、経営陣も継続し、他のCloudやInfrastructure Vendorと自由に契約を結べる状態が維持されます。

明日書くCodeが変わるようなNewsではありません。しかし、大手Infrastructure Vendorがどのようにcoding Model能力へアクセスするかというStructureに変化が起きており、それはAI Coding Stackの構築方法を検討している組織にとって、直接的な意味を持ちます。

## Coding Modelを手に入れる3つの方法、そして拡大した4つ目の方法

多くのEngineering組織がAI Coding能力を選ぶ際、大きく3つの選択肢から選びます。Hosted ModelをAPI経由で利用する方法（Anthropic、OpenAI、Googleなど）、Open-weight Model（Llama、Qwen、DeepSeek系列など）を自社もしくはRentalのGPU上でSelf-hostする方法、そしてModel選定そのものを抽象化したPackaged Product（GitHub Copilot、Cursor、各Vendorの Agent Platform）を購入する方法です。

Nvidia-Poolsideの提携が浮き彫りにしたのは、消費者向けToolだけを見ていると見落としやすい4つ目のPatternです。Infrastructure Vendorが、特化型の「Model Factory」——完成したModelではなく、それを生み出すTraining PipelineとData Engineそのもの——をLicenseし、自社Brandのcoding Model Lineを内製する、という方式です。Nvidiaが購入しているのはPoolsideのModelそのものではなく、そのModelを生み出す仕組みと、それを動かす109名の人材です。

Enterpriseにとってこれが重要なのは、中堅のCloudおよびHardware Vendorがどこへ向かおうとしているかを先取りして示している点です。第三者のAPIを再販するのではなく、Factoryをライセンスして差別化されたIn-house Model Lineを立ち上げる、という選択肢が現実味を帯びてきています。これは今後12〜18ヶ月でEvaluationの対象となるVendor Landscapeを変えます。従来は第三者APIを単に再販していたInfrastructure企業から、「自社Model、ただしLicense済みの仕組み上に構築」というOfferingが増えることが予想されます。

## webhaniが実際にClientへ推奨していること

これによってBuild-vs-Buyの判断の根本原則が変わるわけではありませんが、Due Diligenceに明示的に加えるべき問いが一つ増えました。

```text
Vendor評価Checklist（Model Factoryライセンス提携を踏まえた更新版）:

1. 提示されているModelは、Vendorが自社でTrainingしたものか、
   Factoryから一括ライセンスされたものか、あるいは
   第三者APIの薄いWrapperか？
2. ライセンス/Wrapperの場合: 元となるLicense条件が変わった際、
   価格とRoadmapはどう影響を受けるか？
3. VendorのRoadmapは、公表されていないExclusivity（独占性）に
   依存していないか？（Poolsideの契約は明示的に
   非独占——評価対象のVendorについても書面で必ず確認する）
4. 将来Modelを乗り換える必要が生じた場合、Prompt、
   Fine-tuning Data、評価Harnessをexportできるか？
```

実務上のRiskは「Model Factoryライセンスが悪い」ということではなく、それが「誰が実際にあなたのRoadmapを支配しているか」を見えにくくする点にあります。「自社Model」を差別化要因として掲げるVendorが、実際には他社のライセンス済みFactoryでそれを生成している場合、そのVendorはFactory側のRelease Cadence、Safety方針、価格変更を、開示の有無にかかわらず引き継ぐことになります。

## 具体例: Coding Agent Vendorの評価

200名規模のEngineering組織が3つのCoding Agent Platformから選定する場合を考えます。通常のLatency/Cost/Context Window比較に加えて、今回のDeal以降Evaluation Matrixに加えている問いはこうなります。

```yaml
vendor_evaluation:
  vendor_a:
    model_source: "自社開発のFoundation Model"
    switching_cost: "高い（Agentが特定Modelの挙動にTuning済み）"
    factory_dependency: "開示なし"
  vendor_b:
    model_source: "Licensed Model Factory（条件非開示）"
    switching_cost: "中程度"
    factory_dependency: "不明 — Due Diligenceで直接確認する"
  vendor_c:
    model_source: "薄いWrapper、API経由でProvider交換可能"
    switching_cost: "低い"
    factory_dependency: "該当なし。ただし差別化Moatも小さい"
```

Vendor Aは乗り換えCostが最も高い一方、Accountabilityは最も明確です。Vendor Cは離脱しやすい反面、API Keyと Agent Frameworkがあれば自前でも組める程度の差別化しか提供しません。Vendor Bこそ、今回のDealが教えてくれた追加の問いを投げるべき対象です。

## この提携が実際にAdviceを変える箇所

Latency制約やCompliance要件が厳しく、Open-weight Modelを自社GPU Fleet上でSelf-hostすることを検討しているClientに対しては、Model Factoryライセンスという中間的な選択肢が現実的になってきた点を伝える価値があります。今後、CloudやHardware Vendor（AI専業でなくても）が「Co-branded、Factoryライセンス済み」のModel Tierを、Hosted APIとフルSelf-hostingの中間に用意してくる可能性があります。複数年契約のSelf-hosting Commitmentを結ぶ前に、既存のInfrastructure Vendorへ2027年のRoadmapにこうしたOfferingがあるか確認することを推奨します。

一方、Claude、GPT、Geminiを日々のCoding支援としてAPI経由で選んでいるだけのTeamにとっては、このDealが今日どのModelを選ぶべきかを変えることはありません。これはMarketの次の層に関するSignalであり、現行のEvaluationをやり直す理由にはなりません。

## まとめ

- Model Factoryライセンス（Modelそのものではなく、Training Pipelineを買う方式）は新しい調達Patternであり、従来API再販に留まっていたInfrastructure Vendorから「自社Brand」のAI Coding Productが今後増える可能性が高い。
- Vendor Due Diligenceに一つ問いを加える: そのModelは自社Training、Factoryライセンス、それとも第三者APIのWrapperか。上流の関係が変わった際のExposureはどの程度か。
- 日々AI支援でCodingしているだけの大半のTeamにとっては、これはMarket構造を注視すべきStoryであり、現行のModelやVendor選定を変える理由にはならない。
