10月上旬、npmパッケージ`tensorlake`のバージョン0.5.144が侵害されていたと報じられました。ChainDrop（Shai-Hulud型のワーム）と呼ばれるキャンペーンの一部です。SocketとThe Hacker Newsが報じ、Stingraiが対応チェックリストを公開しています。悪意あるバージョンの公開日は情報源によって10月7日と8日に分かれているため、正確なタイムスタンプには依拠しません。

[依存関係のクールダウンとnpmワーム](/blog/dependency-cooldown-policy-npm-pypi-worms-2026)については以前に書いています。今回はこの事案に固有の教訓、特に「対応の順序」に絞ります。順序を誤ると、被害を広げてしまうからです。

## 報じられている内容

報道によれば、次のとおりです。

- 悪意あるリリースは`preinstall`フックを使っており、`npm install`を実行するだけで発動します。SDKをimportする必要はありません。
- フックは難読化されたローダーを起動し、Bunランタイムを使って、認証情報を盗み自己増殖するペイロードを走らせます。
- 標的は、ローカルファイル、CI環境、KubernetesやVaultの認証情報、AI開発ツールの設定などです。
- Stingraiによると、このリリースはTensorlake自身のリリースワークフローから**有効なprovenance付き**で公開されました。
- Stingraiはさらに、盗まれたGitHubトークンが失効されるとホームディレクトリを削除する監視プロセスがあると報告しています。

最後の点は慎重に扱う必要があります。私たちは独自に検証できていませんが、事実であれば正しい作業順序が変わります。

## provenanceが証明するのは「どこで作られたか」まで

provenance（来歴証明）は、特定のリポジトリの特定のワークフローでビルドされたことを示します。そのワークフローが信頼できるコードを実行していたか、公開用の認証情報が悪用されていないかまでは保証しません。リリースパイプラインを攻撃者が握れば、有効な証明も一緒に手に入ります。

したがってprovenanceは判断材料の一つにとどめます。盗まれたノートPCのトークンでCI外から公開されるケースは防げますが、CI自体の侵害は防げません。

## インストール時の実行を減らす

このシナリオで最も安価な対策は、ライフサイクルスクリプトをデフォルトで実行しないことです。

```bash
# プロジェクトの .npmrc
ignore-scripts=true
```

そのうえで、ネイティブビルドなど本当に必要なパッケージだけを明示的に許可します。最近のnpmやpnpmはこの方向に進んでいますが、許可の具体的な方法はお使いのバージョンのドキュメントで確認してください。

あわせて、公開直後のバージョンを自動で入れない「最小リリース経過期間」も設定します。24〜72時間程度でも、悪意あるバージョンは数時間以内に検知されることが多いため、多くの事案が未遂で済みます。

```yaml
# Renovate の例：新バージョンの提案まで待つ
{
  "minimumReleaseAge": "3 days"
}
```

## インストールしてしまった場合の対応順序

1. **影響範囲の特定。** ロックファイルとCIログから該当バージョンを探します。
   ```bash
   grep -rn "tensorlake" package-lock.json pnpm-lock.yaml yarn.lock 2>/dev/null
   ```
   開発者のPCだけでなく、該当期間にinstallを実行したすべてのマシンとCIランナーを対象にします。
2. **失効の前に隔離する。** 報告されたホーム削除の挙動が事実なら、先にGitHubトークンを失効させるとそれが発動しかねません。ホストをネットワークから切り離し、必要なものを退避し、永続化の仕組みを取り除いてからトークンを回収します。
3. **到達可能なものをすべてローテーションする。** クラウドキー、GitHub・npmのトークン、Kubernetesのサービスアカウントトークン、Vaultトークン、設定ファイルに置いたAIツールのAPIキーなどです。
4. **監査ログを確認する。** 身に覚えのないリポジトリ作成、ワークフロー変更、パッケージ公開がないかを調べます。自己増殖型のワームは、被害者自身の公開権限を使って広がります。
5. **掃除ではなく再構築する。** 影響を受けたランナーや開発マシンは、可能な限り再イメージします。

## AIツール周辺が狙われやすい理由

AIコーディングツールを使う開発マシンには、長期有効なAPIキーがdotfileや環境変数に多数置かれがちです。エージェント基盤系のSDKは、まさにそうしたキーのある環境にインストールされます。可能な範囲で短命な認証情報やシークレットマネージャーへ移し、CIランナーは使い捨てにして、侵害されたインストールが残らないようにします。

## まとめ

- install scriptはデフォルトで無効にし、例外だけを許可リストにします。
- 依存関係の自動更新には、リリース後の経過期間を設けます。
- 有効なprovenanceを、安全なパッケージの証明とみなさないでください。
- ワームが疑われるインシデントでは、「隔離、ローテーション」の順に進め、トークンに触れる前に最新のアドバイザリを読みます。
