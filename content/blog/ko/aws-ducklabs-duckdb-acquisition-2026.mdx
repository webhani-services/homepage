Amazon이 DuckDB를 개발하는 Amsterdam 소재 약 30명 규모 회사 DuckLabs를 인수한다고 발표했습니다. DuckDB는 하루 300만 회 이상 Download되는 In-process OLAP Database입니다. Deal은 8월 말 Close되었고 Team은 2026년 9월 1일부로 AWS에 합류했습니다. 인수 금액은 공개되지 않았습니다. DuckDB 공동 창업자인 Hannes Mühleisen과 Mark Raasveldt는 계속해서 Technical Direction을 주도하며, Team은 Amsterdam에서 개발을 이어갑니다.

중요한 것은 DuckDB, DuckLake, Quack 모두 MIT License Open Source를 그대로 유지하며, 독립된 DuckDB Foundation이 관리를 계속한다는 점입니다. 이는 Redis 식의 Re-licensing 움직임이 아닙니다. 오히려 dbt, Airbyte Connector, MotherDuck을 비롯해 "Data 바로 옆에서 Analytics를 실행"하는 다수의 Tool이 이미 의존하고 있는 Project의 Team과 Roadmap 영향력을 AWS가 사들인 것에 가깝습니다.

## 이번 인수 이전 DuckDB의 위치

DuckDB의 Concept은 항상 단순했습니다. "Analytics를 위한 SQLite". Server도, Cluster도 필요 없이 단일 Binary(또는 Python/Node/Wasm Embed)만으로 Parquet, CSV, 자체 Format에 대해 Columnar OLAP Query를 직접 실행합니다. 대부분의 경우 그 대상은 S3에 있는 File입니다.

```python
import duckdb

# Warehouse를 띄우지 않고 S3의 Parquet File에 직접 Query
result = duckdb.sql("""
    SELECT
        region,
        date_trunc('month', order_date) AS month,
        sum(amount) AS revenue
    FROM read_parquet('s3://sales-data/orders/*.parquet')
    WHERE order_date >= '2026-01-01'
    GROUP BY region, month
    ORDER BY month
""").df()
```

webhani가 진행하는 Client의 Reporting과 Data Exploration 작업 상당수에서, 이는 실제 Query 양에 비해 과도한 Redshift나 Snowflake Warehouse를 대체하는 수단이 되고 있습니다. Cluster를 미리 Provisioning할 필요도, Idle 상태의 Compute 비용도 없이, Query는 코드가 실행되는 곳(Lambda, 노트북, CI Job)에서 그대로 돌아갑니다.

## AWS는 왜 인수했나

The Register의 분석은 AWS Roadmap에서 예상할 수 있는 방향과 일치합니다. S3를 단순 Storage가 아니라 Client가 실제로 "분석하는 곳"으로 만들려는 Amazon의 방향에 부합한다는 것입니다. AWS는 이미 S3 위의 Serverless SQL로 Athena를 제공하고 있지만, Athena는 Network를 통해 호출하는 Managed Service입니다. 반면 DuckDB는 Application Process에 직접 내장되는, 근본적으로 다른 Integration Point이며 지금까지 AWS가 보유하지 못했던 영역입니다.

DuckDB Team을 인수함으로써 AWS는 다음을 확보하게 됩니다.

- SDK, Lambda Runtime, Bedrock의 Data-prep Pipeline에 내장할 수 있는 신뢰도 높은 In-process Query Engine.
- Lakehouse Architecture를 위한 DuckDB의 새로운 Open Table Format인 DuckLake에 대한 영향력. Databricks의 Delta Lake와 Iceberg 생태계에 대한 직접적인 대응 축입니다.
- VC 투자로 인한 지분 희석이나 이전 인수 이력 없이 5년간 업계 최고 수준의 효율적인 Columnar Engine을 만들어온 Engineer Team 확보.

## Architecture 판단에 대한 실무적 영향

기존 Warehouse를 걷어내라는 이야기가 아닙니다. 실무적인 Takeaway는 더 한정적입니다.

1. **DuckDB는 장기적으로 "더 안전한 선택지"가 되었다.** DuckDB를 Production에 도입할 때 자주 나오는 반론이 "5년 뒤에는 누가 Maintain하는가"였습니다. AWS가 뒤를 받쳐주고 Amsterdam에서의 개발 연속성이 확보된 MIT License Project는, 독립 5년 차 Startup이었을 때보다 설득력 있는 답이 됩니다.
2. **Service Wrapper가 아니라 더 긴밀한 S3 통합이 올 가능성이 높다.** `s3://` URL과 별도 인증 설정을 수동으로 구성하는 대신, DuckDB에서 S3의 Partitioned Dataset을 읽는 작업이 Native SDK(boto3나 AWS SDK)를 통해 Credential-aware한 First-class Operation이 될 것으로 예상해야 합니다.
3. **"이 작업에 정말 Warehouse가 필요한가"를 재검토할 가치가 있다.** Analytics Workload가 Bursty하거나, 중소 규모이거나, Application에 내장된 형태(Dashboard, Reporting API, ETL Validation Step 등)라면, S3 Parquet에 대한 DuckDB가 상시 가동되는 Warehouse Cluster보다 저렴하고 단순한 경우가 많습니다.
4. **Lakehouse Project라면 DuckLake를 주시할 가치가 있다.** 새 Lakehouse 구축에서 Iceberg와 Delta Lake를 비교 검토 중이라면, DuckLake는 이제 AWS의 암묵적인 지원을 받고 있습니다. 수년 단위의 Architecture 판단에서 이를 고려해야 합니다.

## 실제로 사용 중인 구체적 Pattern

Warehouse를 정당화하기 어려운 Scheduled Reporting Job에 대해 webhani가 현재 채택하고 있는 Default입니다.

```typescript
// Serverless Reporting Job: Warehouse 없음, Idle Cluster 없음
import duckdb from "duckdb";

const db = new duckdb.Database(":memory:");
const con = db.connect();

con.all(
  `SELECT customer_id, sum(amount) AS total
   FROM read_parquet('s3://reports-bucket/transactions/2026/*.parquet')
   GROUP BY customer_id
   HAVING sum(amount) > 10000`,
  (err, rows) => {
    if (err) throw err;
    // rows를 Reporting Dashboard나 Alerting Pipeline으로 전달
  }
);
```

이를 Scheduled Lambda나 작은 Container에서 실행하면 "Infrastructure"는 실행되어 S3에 Query를 던지고 종료되는 단일 Process뿐입니다. 상시 Warm 상태로 유지할 Cluster도, Idle 과금도 없습니다.

## 정리

- DuckDB 자체는 Open Source이자 MIT License를 그대로 유지합니다. 인수가 바꾸는 것은 "개발 회사"이지 License가 아닙니다.
- 긴급 대응이 아니라 하나의 Signal로 받아들이세요. 기존 DuckDB 사용을 당장 바꿀 필요는 없지만, 새로운 S3 Analytics 판단에서는 AWS의 투자 확대를 고려해야 합니다.
- 신규 Project에서 Warehouse와 Embedded Query Engine 중 선택할 때, DuckDB의 Risk Profile은 개선되었다고 볼 수 있습니다.
- Lakehouse의 Table Format 선정에서는 Open Table Format 뒤에 있는 Vendor가 누구인지가 장기적인 영향을 미치는 만큼, DuckLake의 동향을 계속 지켜보세요.
