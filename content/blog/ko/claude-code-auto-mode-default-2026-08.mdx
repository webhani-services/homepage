2026년 8월 14일, Anthropic은 Claude Code의 Pro/Max/Team Plan에서 신규 Session의 기본 Permission Mode를 Auto Mode로 전환했습니다. Auto Mode는 2026년 3월 Research Preview로 처음 등장한 기능인데, 약 5개월 만에 "선택적으로 켜는 실험 기능"에서 "대부분의 개발자가 기본으로 마주하는 동작"으로 위치가 바뀐 셈입니다.

같은 시점에 Background Job(worktree에서 코드를 수정하는 백그라운드 Session)이 작업 완료 시 자동으로 commit·push를 수행하고, 필요한 경우에만 Draft PR을 여는 동작이 도입되었습니다. 여기에 더해 Permission Check를 우회하는 수법을 막는 보안 수정도 함께 배포되었습니다. 단순한 기능 추가가 아니라, AI Agent에게 위임하는 실행 범위 자체가 확대된 Release로 봐야 합니다.

## 무엇이 바뀌었나

이번 업데이트의 핵심은 세 가지입니다.

1. **기본 Permission Mode 변경**: 신규 Session이 "매번 확인"이 아니라 Auto Mode로 시작합니다.
2. **Background Job의 Git 자동화**: worktree에서의 변경 사항을 자동으로 commit·push하고, Task의 성격에 따라 Draft PR을 자동 생성합니다. 이때 프로젝트의 `CLAUDE.md`에 명시된 Git 운영 규칙을 따릅니다.
3. **Permission Check 강화**: Bash Command의 일부를 Tab이나 보이지 않는 Unicode 문자로 채워 승인 Dialog에서 숨기는 수법이 더 이상 통하지 않습니다.

세 번째 항목은 눈에 잘 띄지 않지만 가장 중요합니다. 승인 Dialog에 표시되는 내용과 실제로 실행되는 Command가 다를 수 있었던 틈을, Auto Mode의 적용 범위가 넓어지는 시점에 맞춰 막은 것은 합리적인 순서입니다.

## 실무적으로 왜 중요한가

Auto Mode가 기본값이 되면서, 개발팀은 "AI에게 어디까지 맡길 것인가"를 명시적으로 설계해야 하는 책임을 지게 되었습니다. 그동안 확인 Dialog를 암묵적인 안전장치로 삼아온 팀이라면, 그 전제가 사라진다는 뜻입니다.

특히 Background Job의 Git 자동화는 주의가 필요합니다. 사람이 실시간으로 지켜보지 않는 Session이 commit·push까지 도달할 수 있다는 것은, `CLAUDE.md`에 적힌 Git 운영 규칙이 더 이상 단순한 문서가 아니라 실제로 집행되는 Policy가 되었다는 의미입니다. 모호하거나 오래된 규칙을 방치하면, 의도하지 않은 Commit Message 위반이나 Branch 운영 이탈이 실제로 발생할 수 있습니다.

## CLAUDE.md를 Policy 문서로 다루기

지금까지 `CLAUDE.md`를 가이드라인 수준으로 여겨온 팀이 많았겠지만, Auto Mode 기본화 이후에는 Agent의 실제 동작을 규정하는 설정 파일로 다뤄야 합니다. 최소한 다음 사항은 명문화하는 것을 권장합니다.

```markdown
## Git 운영 규칙

- Commit은 항상 새로 생성하며, 기존 Commit의 amend는 하지 않는다
- master로의 직접 push는 금지하며, 반드시 Feature Branch를 생성한다
- 파괴적 작업(force push, reset --hard, Branch 삭제)은 반드시 사용자 확인을 거친다
- 자동 생성되는 Draft PR 제목은 `[auto] {변경 요약}` 형식으로 통일한다
```

`settings.json`의 Permission 설정도 함께 점검해두는 것이 안전합니다.

```json
{
  "permissions": {
    "allow": ["Edit", "Read", "Bash(npm run *)", "Bash(git status)"],
    "deny": ["Bash(rm -rf *)", "Bash(git push --force*)"]
  }
}
```

Auto Mode는 "안전하게 실행 가능하다고 판단한 Action"을 자동으로 진행하는 기능이지, 모든 것을 무조건 허용하는 것은 아닙니다. 다만 그 판단 기준은 팀이 명시한 규칙과 Anthropic의 기본 동작이 결합되어 정해지기 때문에, `allow`/`deny` 설정을 비워둔 채 운영하는 것은 여전히 Risk가 큽니다.

## webhani의 권장 사항

1. **단계적으로 전환한다**: 팀 전체를 한 번에 Auto Mode로 옮기지 말고, Risk가 낮은 Repository나 개인 검증 환경에서 먼저 동작을 확인합니다.
2. **Draft PR도 일반 PR과 동일하게 Review한다**: 자동 생성된 PR이라고 Review를 생략하지 않습니다. "왜 이 변경이 필요하다고 판단했는가"를 확인하는 습관을 들입니다.
3. **`CLAUDE.md`를 정기적으로 점검한다**: 오래되거나 모호한 지침이 남아 있지 않은지 분기별로 재검토합니다.
4. **보안 수정 적용 여부를 확인한다**: CI와 Local 환경의 Claude Code Version이 Permission Check 강화를 포함한 최신 버전인지 확인합니다.

Auto Mode의 기본화는 AI Coding Assistant가 "제안하는" 단계를 넘어 "실행하는" 단계로 본격적으로 이동하고 있음을 보여주는 하나의 이정표입니다. webhani는 Client 기업의 AI 도입 지원 과정에서, 이러한 Permission Model 변화를 전제로 한 `CLAUDE.md` 설계와 Permission Policy 수립을 지속적으로 지원하고 있습니다.
