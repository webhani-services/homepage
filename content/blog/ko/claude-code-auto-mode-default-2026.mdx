## Auto Mode 도입 — 무엇이 바뀌었는가

8월 14일, Anthropic이 Claude Code의 권한 관리 체계를 개편했습니다. Pro, Max, Team 사용자가 기본으로 받게 되는 모드가 이제 "Auto Mode"입니다.

지금까지 Claude Code는 파일 읽기, 쉘 명령 실행, Git 작업 하나하나마다 사람의 확인을 요청했습니다. 개발자는 매번 팝업 다이어로그에 "진행할까요?"라고 답해야 했습니다. 이것이 안전성을 보장하는 대신, 개발 속도를 떨어뜨렸습니다.

Auto Mode에서는 Anthropic이 구축한 분류기(classifier)가 각 작업을 사전에 판정합니다. "읽기 작업이므로 안전" → 자동 승인. "git push 작업이므로 확인 필요" → 인간 승인 요청. 이 분류 과정에 추가 token 비용도 발생하지 않습니다.

표면적으로는 UI 개선처럼 보이지만, 실제로는 AI 개발 도구와 인간의 상호작용 방식이 근본적으로 변한 것입니다.

## Auto Mode의 작동 원리

분류기는 화이트리스트 방식으로 동작합니다. 패턴을 학습하고 판정합니다:

- 파일 읽기 → 부작용 없음 → 즉시 승인
- 테스트 실행 → 로컬 환경만 영향 → 자동 승인
- feature 브랜치 생성 → 안전한 Git 작업 → 자동 승인
- npm publish → 외부 상태 변경 → 인간 승인 필요
- 프로덕션 데이터베이스 접근 → 위험 → 인간 승인 필요

분류기의 핵심은 **의도를 읽는다**는 점입니다. 단순 구문 매칭이 아니라, 작업의 맥락과 결과를 평가합니다. `git add`, `git commit` 후 push 시도라면, push 단계에서만 게이트가 작동합니다.

또한 이번 업데이트와 함께 Claude Code에는 추가 기능도 포함됩니다. GitLab Merge Request 지원으로 GitHub뿐 아니라 GitLab 워크플로우도 연결되고, 자체 호스팅 러너의 시작 속도가 개선되었습니다. Gateway와 Plugin 검증이 강화되어 설정 오류 위험이 줄어들었습니다. 데이터 레지던시나 컴플라이언스가 중요한 조직을 위해 자체 인프라에서 Claude Code 클라우드 세션을 실행할 수 있는 기능도 공개 베타로 제공됩니다(Team/Enterprise).

## 컨설팅 팀 관점: 속도 증대와 감시 방식의 전환

Webhani가 클라이언트 프로젝트에서 Claude Code를 사용하며 발견한 변화입니다.

### 효율성이 눈에 띄는 부분

새로운 클라이언트 프로젝트 온보딩이 크게 가속됩니다. 시스템 구조를 이해하려면 수십 개의 파일을 읽고, 타입 정의를 확인하고, 설정 파일들을 검토해야 합니다. 기존에는 권한 다이어로그가 이 과정을 단편화했습니다. Auto Mode에서는 Claude Code가 프로젝트 구조, 빌드 설정, 타입 정의를 중단 없이 탐색합니다.

실제 사례: 주니어 개발자가 45분을 권한 확인에 쓰던 초기 조사 작업이 15분으로 단축되었습니다. 탐색이 빨라졌을 뿐 아니라, AI의 제안을 더 집중해서 검토할 여유가 생깁니다.

버그 추적이나 성능 문제 진단도 마찬가지입니다. 실행 경로를 여러 파일에 걸쳐 따라가야 하는데, 권한 게이트 없이 Claude Code가 흐름을 추적합니다. 최종 검증은 여전히 인간이 하지만, 인간이 해야 할 일이 '허가'에서 '검증'으로 이동합니다.

### 감시 책임의 전환

효율성 이득의 대가로, 감시 방식이 근본적으로 바뀝니다. 이제 작업 **전**에 "이 명령을 실행할까요?"라고 묻지 않습니다. 대신 작업 **후**에 "무엇이 실행되었나?"를 확인합니다.

이것은 퇴행이 아닙니다. 분류기는 피곤한 인간보다 일관되고 정확한 판정을 내립니다. 하지만 문화와 프로세스가 바뀝니다.

Webhani는 다음과 같이 대응합니다:

**1단계: 사전 제약 설정**
Claude Code 세션 시작 전에 명확한 제한을 문서화합니다:

```text
금지 사항:
- 프로덕션 데이터베이스 접근 명령
- AWS Console 접근
- 결제 시스템과의 상호작용
- .env 파일 수정 (별도 지시 없이)
- npm 패키지 삭제
```

분류기도 이 제약을 존중하도록 설계되어 있습니다.

**2단계: 작업 로그 정기 검토**
Claude Code는 모든 작업을 기록합니다. 승인된 것, 확인을 기다린 것 모두. 팀은 주 1회 로그의 일부(샘플링)를 검토합니다. 이상한 패턴을 찾습니다: 예상 외의 브랜치에서 git pull이 자동 승인되었다든지, 수정되면 안 되는 디렉토리가 변경되었다든지.

**3단계: 프로젝트 단계별 권한 차등 운영**
초기 리서치 단계 → 자동 승인 범위 넓게
구현 단계 → 제약 강화
릴리스 준비 단계 → 모든 쓰기 작업 수동 검토

이것은 위험도 변화에 맞춘 설계입니다.

## Auto Mode도 커버하지 못하는 영역

분류기는 기술적 게이트일 뿐입니다. 다음 책임들은 여전히 인간만 맡을 수 있습니다:

**생성 코드의 정확성**
테스트 실행은 자동 승인되지만, "테스트가 통과하니까 논리가 맞다"는 아닙니다. 알고리즘 정확성, 비즈니스 요구사항 준수는 인간 검토가 필수입니다.

**비용 영향이 있는 API 호출**
AWS SDK 실행은 승인되지만, "이 추론 호출이 $200이 드는가"는 판정할 수 없습니다. 과금 서비스, 결제 게이트웨이, 메터링 기반 서비스 호출은 비즈니스 영향을 인간이 평가해야 합니다.

**보안 민감 설정 변경**
데이터베이스 암호 변경이나 API 키 수정은 기술적으로는 '안전한 파일 쓰기'입니다. 하지만 프로덕션 환경에서는 그 결정 자체가 보안 사항입니다.

**컴플라이언스 및 감사 기록**
클라이언트가 금융, 헬스케어 같은 규제 산업에 있다면, "Claude Code가 43개 작업을 자동 실행했음"이 감사 로그에 기록되어야 할 수도 있습니다. 분류기는 감사 요구사항을 모릅니다. 당신이 알아야 합니다.

## 실전 팀 운영 패턴

Next.js 애플리케이션 클라이언트 프로젝트에서의 구체적 사례입니다:

```text
세션 설정:
"사용자 인증 모듈을 개선하는 중입니다.
src/auth/route.ts의 기존 로그인 구현을 읽고
타입 안전성을 개선할 리팩토링 제안을 해주세요.

금지 사항:
- package.json 수정
- 커밋 또는 푸시
- 파일 삭제

제안은 Markdown 문서 형태로만 제시해주세요."
```

이 설정에서:
- 파일 읽기 → 자동 진행 (안전함)
- TypeScript 베스트프랙티스 비교 → 자동 진행 (출력만)
- 제안 생성 → 자동 진행 (출력만)
- package.json 접근 → 확인 필요 (명시 제약)
- 모든 Git 작업 → 확인 필요 (구조적 게이트)

개발자의 역할은 제안을 검토한 후 적용 여부를 결정하는 것입니다.

## 다중 엔지니어 감시 체계

큰 팀의 경우, Webhani는 Claude Code 출력에 경량의 코드 리뷰 게이트를 권장합니다. 모든 줄을 리뷰하지는 않되:

- Claude Code가 생성한 새 파일 (5분 스캔)
- 핵심 경로 변경 (인증, 결제, 접근 제어)
- 제안된 의존성 업데이트

분류기가 이미 대부분의 위험 작업을 필터링했으므로, 이것은 두 번째 판정이 아니라 **출력 검증**입니다.

## 클라이언트 문맥에 따른 설정

### 스타트업/내부 프로젝트
Auto Mode 최대 활용. 제약은 가벼움("프로덕션 AWS 변경 금지"). 속도 이득이 감시 비용보다 중요합니다.

### 중견 SaaS (컴플라이언스 필요)
중간 제약. 파일 읽기와 안전한 Git 작업은 자동 승인. 쉘 명령, 배포, DB 스키마 변경은 확인 필요. 모든 작업 로깅, 30일 보관.

### 엔터프라이즈 (엄격한 변경 제어)
강한 제약. 읽기만 자동 승인. 모든 쓰기, 모든 쉘 명령, Git push는 확인 필요. 모든 세션 로깅 및 주간 검토.

## 더 큰 그림

Auto Mode는 AI 개발 도구가 성숙해가는 과정을 보여줍니다. 초기 AI 도구는 자동완성처럼 작동했고 지속적 감시가 필요했습니다. 도구가 진화하면서 감시는 "허가 게이트"에서 "출력 검증"으로 이동합니다. 이것이 더 효율적입니다. AI는 안전 판정에서 일관되고 인간은 정확성 검증에 집중하기 때문입니다.

핵심은 이 전환을 인식하는 것입니다. Auto Mode를 "감시 없는 자동 로봇"으로 간주하는 팀은 결국 버그나 컴플라이언스 위반을 배포합니다. "더 빠른 탐색, 같은 수준의 리뷰"로 접근하는 팀이 속도와 안전성을 동시에 얻습니다.

컨설팅 회사 입장에서 Webhani는 이 변화가 클라이언트 프로젝트의 경제성을 개선한다고 봅니다. AI 지원 개발의 허가 비용이 내려가고, 검증 책임은 유지됩니다. 최종 효과는 더 빠른 납기인데, 팀이 감시 지점을 의도적으로 설계한다면 안정성도 보존됩니다.
