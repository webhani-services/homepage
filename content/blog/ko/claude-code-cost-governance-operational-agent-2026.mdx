## Coding Assistant가 아니라 운영 Release 같은 변경 이력

Anthropic의 최신 Claude Code Release에는 구조화된 Feedback Draft 작성, 내장 Cost 최적화 도구, Plugin 및 Session Safeguard 강화라는 세 가지 기능이 추가되었습니다. 화려한 Model 성능 향상이 아닙니다. 도구가 "실험 단계"를 벗어나 다른 Infrastructure가 의존하는 진짜 Infrastructure가 되었을 때 비로소 등장하는, 지루하지만 필수적인 기능들입니다.

바로 이 지점이 핵심입니다. Claude Code는 "Chat 창이 달린 똑똑한 자동완성"에서, 반자율적으로 동작하며 팀의 API Budget을 소비하고 Plugin과 Background Session을 통해 편집 중인 File 밖까지 영향을 미치는 Agent로 조용히 진화했습니다. webhani는 지난 1년 가까이 Claude Code를 Client의 CI Pipeline과 사내 개발 Workflow에 통합해왔는데, 반복적으로 확인되는 패턴은 항상 같습니다. 도구의 성숙 속도가 그를 감싸는 Governance 정비 속도를 앞지른다는 것입니다. 이번 Release는 Anthropic이 그 Gap의 일부를 메운 것이고, 나머지는 도입하는 팀의 몫입니다.

## 기존 Mental Model이 통하지 않는 이유

Claude Code를 "똑똑한 Autocomplete"로만 본다면 평가 기준은 Code 품질 하나로 끝납니다. 하지만 CI에서 상시 실행되는 Dev Assistant로 운영하거나, Plugin이 설치된 여러 Background Session을 동시에 돌리는 단계에 들어서면, 다른 Infrastructure였다면 당연히 통제 장치가 필요했을 세 가지 속성을 암묵적으로 Agent에게 부여한 셈이 됩니다.

- **사람이 매번 승인하지 않아도 소비되는 Budget.** Turn마다 여러 Tool 호출을 반복하는 Agent Session은 단발성 Chat 응답과는 비교가 안 되는 속도로 비용이 누적됩니다.
- **실제 System에 대한 쓰기 권한.** Editor에 열려 있는 File뿐 아니라, 부여된 Plugin과 Permission이 허용하는 범위 전체입니다.
- **Session 간 지속되는 State.** 이력, 환경 Context 속 Credential, Cache된 Tool 결과 등, 문제가 생겼을 때 감사 추적(Audit Trail)이 필요한 종류의 State입니다.

Cost 최적화 도구와 Session Safeguard가 나온 이유는 Anthropic이 이 세 가지 속성을 제품의 1급 표면으로 다루기 시작했기 때문입니다. 도입하는 팀도 같은 태도를 취해야 합니다.

## 최소한으로 효과를 보는 Governance Framework

거창한 Process는 필요 없습니다. Client 프로젝트에서 흔히 보는 실패 Pattern을 커버하려면 아래 세 가지면 충분합니다.

**1. Session 단위로 연결된 Budget Alert.** CI Job 안의 폭주 Loop와 팀 전체에 걸친 서서히 누적되는 비용 증가는 서로 다른 문제이며, 각각 다른 방식으로 감지해야 합니다.

```typescript
// scripts/agent-spend-guard.ts
import Anthropic from "@anthropic-ai/sdk";

const SESSION_BUDGET_USD = 5;    // CI Job당
const DAILY_BUDGET_USD = 150;    // 팀 전체 일일 기준

async function trackSpend(usage: Anthropic.Usage, sessionId: string) {
  const inputCost = usage.input_tokens * 0.000003;
  const outputCost = usage.output_tokens * 0.000015;
  const sessionTotal = await incrementSessionSpend(sessionId, inputCost + outputCost);

  if (sessionTotal > SESSION_BUDGET_USD) {
    await killSession(sessionId, "session budget exceeded");
  }

  const dailyTotal = await getDailySpend();
  if (dailyTotal > DAILY_BUDGET_USD * 0.8) {
    await notifySlack(`Agent spend at ${Math.round((dailyTotal / DAILY_BUDGET_USD) * 100)}% of daily budget`);
  }
}
```

의도적으로 단순하게 만든 구현입니다. 목표는 정교한 FinOps Dashboard가 아니라, 폭주하는 Loop가 Invoice의 거액 항목으로 이어지기 전에 작동하는 Circuit Breaker입니다.

**2. Dependency Review와 동일한 태도로 다루는 Plugin Allowlist화.** Claude Code Plugin은 기능적으로 Tool 호출 권한을 가진 third-party Package입니다. npm Dependency에 적용하는 것과 같은 규율, 즉 Version 고정, 업데이트 시 Diff Review, 각 Plugin이 접근 가능한 범위 제한을 권장합니다.

```yaml
# .claude/settings.json (일부)
{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Edit(src/**)",
      "Read(**)"
    ],
    "deny": [
      "Bash(curl:*)",
      "Bash(rm -rf:*)",
      "Edit(.env*)"
    ]
  },
  "plugins": {
    "allowlist": ["internal-lint-fixer@1.2.0"],
    "requireApprovalForNew": true
  }
}
```

여기서는 Allow List보다 Deny List가 더 중요합니다. 저희가 실제로 겪은 Incident 대부분은 Plugin이 특이한 동작을 해서가 아니라, 아무도 제한해야 한다고 생각하지 못한 Tool에 Agent가 손을 뻗어서 발생했습니다.

**3. Session이 끝난 뒤에도 남는 Audit Trail.** Background Session이 몇 시간 뒤 다시 재개되거나 다른 Engineer에게 인계될 때, 앞으로 무엇을 할지가 아니라 지금까지 무엇을 했는지 기록이 필요합니다. Tool 호출과 그 인자는 Agent 자체 Context 바깥의 Store에 Log를 남겨, 혼란스럽거나 손상된 Session이 자신의 이력을 지울 수 없도록 해야 합니다.

## Verbose와 Concise, 엄격 Mode와 편의성의 균형

Cost 도구와 Safeguard에는 실질적인 Trade-off가 따릅니다. Permission Scope를 엄격히 하고 Budget Guard를 조일수록, 정당한 작업도 Approval을 기다리며 멈추는 빈도가 늘어납니다. webhani의 기준은 Deploy Script, Secret, Infrastructure as Code에 관련된 작업은 엄격 Mode, 일상적인 Refactor나 Test 생성처럼 실패해도 "CI Run 실패" 정도로 끝나는 작업은 관대한 Mode로 나누는 것입니다.

| Context | Permission Mode | Budget Guard |
|---|---|---|
| 내부 Utility Refactor | 관대 | Soft Alert만 |
| CI 기반 Code Review | 관대 | Session 단위 Cap |
| Deploy / IaC File 수정 | 엄격 Allowlist | Hard Stop + 사람 승인 |
| Plugin 기반 자동화 | 명시적 Allowlist | Plugin 단위 Cap |

## 핵심 요점

- **Claude Code가 Cost 도구와 강화된 Safeguard를 출시한 것 자체가 중요한 Signal입니다.** 도구가 무인 Infrastructure로 사용되고 있다는 현실을 Anthropic이 인정하고 그에 맞춰 개발하고 있다는 증거입니다.
- **Budget Guard는 Session 단위로 Scope 되어야 합니다.** 팀 전체 집계만으로는 월별 청구서에서 놀라기 전에 폭주 Loop를 막을 수 없습니다.
- **Plugin은 Dependency로 취급하세요.** Version 고정, Default Deny, 새 Tool Access 부여 전 Review가 기본입니다.
- **Permission의 엄격함은 Blast Radius에 맞추세요.** Deploy Script와 Secret은 Hard Stop이 필요하지만, 일상적인 Code 생성에 같은 수준의 마찰은 불필요합니다.
