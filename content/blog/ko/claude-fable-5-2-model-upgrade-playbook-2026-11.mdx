2026년 11월 9일, Anthropic이 Claude Fable 5.2와 Claude Mythos 5.2를 출시했습니다. 두 Model은 같은 기반 Model을 공유하며, Fable은 일반 제공 버전이고 Mythos는 심사를 통과한 조직만 사용할 수 있습니다. 대부분의 팀에게 중요한 것은 Fable 5.2입니다.

성능 수치는 이미 여러 곳에서 다뤘으니 간단히 정리하고, 이 글에서는 실제로 손이 많이 가는 부분에 집중합니다. 바로 Production Workload를 한 Model 버전에서 다음 버전으로 품질 저하 없이 옮기는 방법입니다.

## 무엇이 바뀌었나

- **Model ID:** `claude-fable-5-2`, Context Window는 1M Token입니다.
- **가격:** Input 100만 Token당 8달러, Output 40달러, Cache 읽기는 0.20달러입니다(Claude Code changelog 기준). InfoWorld 보도에 따르면 Fable 5.1은 10달러/50달러였습니다.
- **속도:** Anthropic은 Output이 5.1 세대보다 최대 30% 빠르다고 밝혔습니다.
- **Coding:** Anthropic은 FrontierSWE v2에서 69.9%(Claude Opus 5.5는 62.3%)를 기록했다고 발표했습니다. Vendor가 발표한 Benchmark이므로 "우리 코드에서도 좋아진다"는 근거가 아니라 "테스트해 볼 이유"로 받아들이는 것이 맞습니다.
- **Claude Code:** v2.1.321부터 Fable 5.2가 기본 Fable Model입니다. 저장된 Fable 5.1 선택은 `fable` Alias로 자동 이동합니다. Pro/Max Plan은 즉시, Team/Enterprise Plan은 조직이 허용한 시점부터입니다. 되돌리려면 `/model claude-fable-5-1`을 사용합니다.

가장 먼저 체감하게 될 변화는 마지막 항목입니다. 팀에서 Claude Code를 쓰고 있다면, 이미 많은 팀원이 본인도 모르는 사이에 5.2로 작업하고 있을 가능성이 높습니다.

## Alias와 고정 Model ID

Claude Code의 동작은 일반적인 원칙 하나를 잘 보여 줍니다. `fable` 같은 Alias는 가리키는 대상이 바뀝니다. 사람이 매번 결과를 확인하는 대화형 용도라면 문제없습니다. 하지만 티켓 분류나 SQL 생성을 하는 Backend Service에서는 Output 형식의 작은 변화가 후단 Parser를 깨뜨릴 수 있습니다.

webhani는 다음 기준으로 구분합니다.

| 용도 | 권장 |
| --- | --- |
| 대화형 도구(IDE, Claude Code, Chat) | Alias 사용 가능. 변경 사실은 팀에 공유 |
| Batch 작업, Backend API | Configuration에서 Model ID를 완전히 고정 |
| 평가 Harness | 비교 대상 양쪽 모두 명시적인 ID 사용 |

Model ID는 코드가 아니라 Configuration에 두어서, 배포와 Rollback을 설정 변경만으로 처리할 수 있게 합니다.

```ts
// config/llm.ts
export const llmConfig = {
  primaryModel: process.env.LLM_PRIMARY_MODEL ?? "claude-fable-5-1",
  candidateModel: process.env.LLM_CANDIDATE_MODEL ?? "claude-fable-5-2",
  // Rollout 중 후보 Model로 보내는 Traffic 비율(%)
  candidateRatio: Number(process.env.LLM_CANDIDATE_RATIO ?? "0"),
};

export function pickModel(requestId: string): string {
  // Retry 시에도 같은 Model로 가도록 결정적으로 분배
  const bucket = [...requestId].reduce((a, c) => (a + c.charCodeAt(0)) % 100, 0);
  return bucket < llmConfig.candidateRatio
    ? llmConfig.candidateModel
    : llmConfig.primaryModel;
}
```

## 먼저 자체 평가를 돌린다

공개 Benchmark는 다른 사람의 Task를 측정한 결과입니다. Production을 건드리기 전에, 익명화한 실제 Input 세트를 두 Model에 똑같이 보내고 해당 Workload에서 중요한 기준으로 비교합니다.

```ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

type Case = { id: string; prompt: string; check: (out: string) => boolean };

async function runCase(model: string, c: Case) {
  const started = Date.now();
  const res = await client.messages.create({
    model,
    max_tokens: 2048,
    messages: [{ role: "user", content: c.prompt }],
  });
  const text = res.content
    .filter((b) => b.type === "text")
    .map((b) => b.text)
    .join("");
  return {
    id: c.id,
    model,
    passed: c.check(text),
    ms: Date.now() - started,
    inputTokens: res.usage.input_tokens,
    outputTokens: res.usage.output_tokens,
  };
}

export async function compare(cases: Case[], a: string, b: string) {
  const results = [];
  for (const c of cases) {
    results.push(await runCase(a, c), await runCase(b, c));
  }
  return results;
}
```

핵심은 `check` 함수에 있습니다. JSON을 반환하는 Endpoint라면 Parse가 되는지, Schema에 맞는지 확인합니다. Code 생성이라면 생성된 코드를 Test로 실행합니다. 요약 작업이라면 다른 Model로 Rubric 채점을 해도 되지만, 일부 Sample은 사람이 직접 확인합니다.

통과율 외에 함께 보는 항목은 세 가지입니다.

1. **Output 길이:** 새 Model은 답변이 길어지는 경향이 있습니다. 이번에는 Output 단가가 Input의 5배이므로, 답변이 20% 길어지면 가격 인하 효과가 상쇄될 수 있습니다.
2. **형식 변화:** Plain Text였던 부분이 Markdown이 되거나, JSON 앞에 설명 문구가 붙거나, Heading 레벨이 바뀌는 경우입니다.
3. **거부·과도한 신중함의 변화:** Anthropic은 5.1보다 차단이 줄었다고 밝혔습니다. 자사 Domain에서 늘었는지 줄었는지 양방향으로 확인합니다.

## 비용 계산을 다시 한다

정가 인하는 사실이지만, 실제 청구액은 Token 구성에 따라 달라집니다. 하루 Input 100만 Token, Output 20만 Token인 Workload로 계산해 보겠습니다.

- Fable 5.1: 1 × 10달러 + 0.2 × 50달러 = **하루 20달러**
- Fable 5.2: 1 × 8달러 + 0.2 × 40달러 = **하루 16달러**

Output 길이가 같다면 20% 절감입니다. 그런데 평가 결과 5.2의 Output이 25% 더 길다면 하루 18달러가 되어 절감 폭은 10%로 줄어듭니다. Prompt Caching을 많이 쓴다면 Input 쪽은 0.20달러의 Cache 읽기 단가가 지배적이 되어 비교 결과가 또 달라집니다. 평가 중에 기록한 `usage` 값으로 직접 계산해 보시기 바랍니다.

## 단계적 Rollout

평가 결과가 괜찮다면 앞의 Configuration을 이용해 단계적으로 전환합니다.

1. **5%** Traffic으로 하루. Error Rate, Latency, 후단 Parse 실패를 Monitoring합니다.
2. **50%** 로 며칠. Request당 비용과 사용자 관점의 품질 지표를 비교합니다.
3. **100%** 로 전환. 최소 2주 정도는 이전 Model ID를 Rollback 대상으로 Configuration에 남겨 둡니다.

팀에서 Claude Code를 쓰는 경우에는 공유가 이에 해당합니다. 기본 Model이 바뀌었다는 점, 되돌리는 방법, 그리고 공유 Prompt나 Custom Command, CLAUDE.md 기반 Workflow에서 이상한 점이 있으면 알려 달라는 점을 전달합니다.

## 정리

- Fable 5.2는 Token 단가가 내려갔고 Coding 성능도 향상됐다고 발표되었습니다. 빠르게 평가해 볼 만합니다.
- Alias는 대상이 바뀝니다. 기계가 Output을 소비하는 곳에서는 Model ID를 완전히 고정합니다.
- 어떤 Leaderboard보다 자체 평가 세트가 유용합니다. 한 번 만들어 두면 이후 모든 Model 출시에 재사용할 수 있습니다.
- 절감 효과를 보고하기 전에 실제 Output 길이로 비용을 다시 계산합니다.

webhani는 LLM 기능에 이런 평가와 Rollout 체계를 갖추도록 지원하고 있습니다. 새 Model 출시를 리스크가 아니라 일상적인 변경으로 다룰 수 있도록 하기 위해서입니다.
