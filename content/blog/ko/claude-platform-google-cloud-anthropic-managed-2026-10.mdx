Anthropic이 자사가 직접 운영하는 Claude API를 Google Cloud를 통해 제공하기 시작했다고 발표했습니다. 인증은 Google Cloud IAM을 사용하고, 비용은 Google Cloud 청구서에 합산되어 기존 Commitment에서 차감됩니다. 발표에 따르면 Claude Opus 5.5의 Fast mode도 이 경로에서 사용할 수 있습니다. Claude는 이미 Google-managed 형태로 GCP에서 쓸 수 있었기 때문에, 이제 질문은 "GCP에서 Claude를 쓸 수 있는가"가 아니라 "두 경로 중 어느 쪽이 우리 제약에 맞는가"입니다.

참고로 Fast mode 지원 여부와 가격 등은 2차 자료마다 내용이 엇갈립니다. 아래 내용은 판단 틀로 활용하시고, 구체적인 수치는 Anthropic과 Google의 최신 문서에서 확인하시기 바랍니다.

## 두 경로의 차이

실무에서 중요한 차이는 "누가 운영하는가"와 "사용할 수 있는 기능 범위"입니다.

| | Google-managed | Anthropic-managed |
|---|---|---|
| API 운영 주체 | Google | Anthropic |
| 데이터 처리자 | Google | Anthropic (Anthropic 약관 적용) |
| 인증 | Google Cloud IAM | Google Cloud IAM |
| 과금 | Google Cloud | Google Cloud (Commitment 차감) |
| 신규 기능 반영 | Google의 통합 일정에 따름 | Anthropic 플랫폼을 따라감 |

보안·법무 검토에서 "데이터 처리자는 Google만 승인"이라는 결론이 났다면 Google-managed가 여전히 안전한 선택입니다. 반대로 "하이퍼스케일러를 거치면 신규 기능이 늦게 들어온다"는 점이 걸림돌이었다면 Anthropic-managed가 이를 해소해 줍니다. 청구가 Google Cloud 안에 남기 때문에 별도의 구매 절차도 필요 없습니다.

## 운영 측면에서 달라지는 점

고객사의 LLM 도입에서 막히는 지점은 대개 모델 품질이 아니라 구매 절차, Key 관리, 비용 배분입니다. 모델 API가 이미 운영 중인 클라우드 계정 안으로 들어오면 세 가지가 단순해집니다.

- **장기 API Key가 필요 없습니다.** Service Account로 인증하므로 수동 Rotation이 없습니다. `.env`에서 Secret 하나가 사라지는 것만으로도 보안상 개선입니다.
- **청구와 예산이 일원화됩니다.** GCP에는 이미 Label, Budget, Alert 체계가 있습니다. LLM 비용이 아무도 관리하지 않는 SaaS 구독이 아니라 일반 클라우드 비용으로 보이게 됩니다.
- **감사 추적을 그대로 활용합니다.** IAM Policy와 Audit Log가 다른 서비스와 동일한 방식으로 적용됩니다.

반면 Rate Limit, Region, 사용 가능한 모델은 경로마다 다릅니다. 운영 Workload를 올리기 전에 반드시 확인하십시오.

## 애플리케이션을 Portable하게 유지하기

흔한 실수는 애플리케이션 코드를 특정 Provider의 Client에 직접 묶어 두는 것입니다. 얇은 경계 하나만 두면 경로 선택을 나중에 되돌릴 수 있습니다.

```typescript
// llm/client.ts
export interface ChatRequest {
  system: string;
  userMessage: string;
  maxTokens: number;
}

export interface LlmClient {
  complete(req: ChatRequest): Promise<string>;
}

export type Route = "anthropic-direct" | "gcp-anthropic-managed" | "gcp-google-managed";

export function createLlmClient(route: Route): LlmClient {
  switch (route) {
    case "anthropic-direct":
      return new AnthropicDirectClient();
    case "gcp-anthropic-managed":
      return new GcpAnthropicManagedClient();
    case "gcp-google-managed":
      return new GcpGoogleManagedClient();
  }
}
```

인증, Model ID, 에러 매핑은 각 구현체가 맡고, 나머지 애플리케이션은 `LlmClient`에만 의존합니다. 경로는 코드 변경이 아니라 설정으로 선택합니다.

```typescript
const client = createLlmClient(
  (process.env.LLM_ROUTE as Route) ?? "anthropic-direct",
);
```

Model ID는 특히 주의가 필요합니다. 같은 모델이라도 경로에 따라 ID가 다를 수 있으므로, 문자열 리터럴을 코드 곳곳에 흩뿌리지 말고 한 곳의 표로 관리하십시오.

```typescript
const MODEL_IDS: Record<Route, Record<"fast" | "balanced", string>> = {
  "anthropic-direct": { fast: "claude-haiku-5-5", balanced: "claude-sonnet-5-5" },
  // 각 Provider 문서를 보고 채웁니다 (경로마다 ID가 다를 수 있음)
  "gcp-anthropic-managed": { fast: "", balanced: "" },
  "gcp-google-managed": { fast: "", balanced: "" },
};
```

## 경로 선택 체크리스트

경로를 정하기 전에 다음 다섯 가지를 확인합니다.

1. 자사 및 고객사와의 계약상 데이터 처리자는 어느 법인이어야 하는가.
2. Anthropic 플랫폼에는 나왔지만 다른 경로에는 아직 없는 기능이 필요한가.
3. 필요한 Model과 Region이 로드맵이 아니라 오늘 해당 경로에서 사용 가능한가.
4. Retry를 포함한 예상 트래픽이 Quota와 Rate Limit 안에 들어오는가.
5. Label이나 Project 단위로 제품별 LLM 비용을 배분할 수 있는가.

1번과 2번의 답이 충돌한다면, 그것이 진짜 의사결정이며 기술이 아닌 비즈니스 판단입니다.
