2026년 8월 2일, EU AI Act 제50조(투명성 의무)가 시행되었습니다. 유럽위원회는 7월 20일 관련 Guideline을 채택했으며, 적용 대상은 "고위험 AI System"에 국한되지 않습니다. Chatbot, 음성 Assistant, AI Agent, AI 생성 Content를 다루는 거의 모든 Service가 대상입니다. 위반 시 제재금은 최대 1,500만 유로, 또는 전 세계 연간 매출의 3% 중 높은 금액입니다.

webhani는 AI/LLM을 접목한 Web Application 개발을 진행하고 있는데, 이 규제는 "EU 지역 사용자에게 Service를 제공하는지"로 적용 여부가 결정되기 때문에 본사 위치와 무관하게 적용될 수 있습니다. 이번 글에서는 개발자 관점에서 제50조가 실제로 무엇을 요구하는지 정리합니다.

## 제50조가 규정하는 4가지 시나리오

제50조는 Provider(AI System을 개발하여 시장에 제공하는 자)와 Deployer(자신의 권한으로 AI System을 사용하는 자)를 구분하여, 다음 4가지 시나리오에서의 공개 의무를 규정합니다.

1. **AI와 직접 상호작용하는 System** (Chatbot, 음성 Assistant, AI Agent): 사용자가 AI와 대화하고 있다는 사실이 자명하지 않은 경우 이를 공개해야 함
2. **감정 인식·생체 분류 System**: 사용 사실을 대상자에게 고지할 의무
3. **AI 생성·조작 Content** (Deepfake 포함 이미지·음성·영상): Content가 인위적으로 생성·조작되었음을 명시
4. **공익적 사안을 다루는 AI 생성 텍스트**: 기계 판독 가능한 형식으로 Marking하여 탐지 가능하도록 처리

이 중 Web 개발자에게 가장 영향이 큰 것은 1번과 4번입니다.

## 구현 패턴: Chatbot 공개 의무

"자명하지 않은 경우 공개 필요"라는 조항은 다소 모호하지만, 실무적으로는 UI에 명시적인 Label을 상시 노출하는 것이 안전한 해석입니다.

```tsx
// components/ChatDisclosure.tsx
export function ChatDisclosure() {
  return (
    <div
      role="status"
      aria-live="polite"
      className="text-xs text-muted-foreground border-b px-3 py-2"
    >
      본 Chat은 AI Assistant가 응답합니다.
    </div>
  );
}
```

대화 시작 시 Banner 노출만으로는 부족합니다. 세션이 길게 이어지는 Support Chat 등에서는 사용자가 대화 중간에 참여하더라도 공개 문구가 계속 보이는 위치에 고정 배치하는 것을 권장합니다.

## 구현 패턴: AI 생성 Content Marking

제50조 2항은 AI 생성 텍스트와 이미지에 기계 판독 가능한 Marking을 요구합니다. 2026년 5월 AI Omnibus 잠정 합의에 따라 시행일 이전부터 시장에 존재하던 생성 AI System은 2026년 12월 2일까지 유예 기간이 주어지지만, 신규 개발에서는 처음부터 대응하는 것이 좋습니다.

C2PA(Coalition for Content Provenance and Authenticity)의 Content Credentials는 이미지·영상에 암호 서명된 Metadata를 삽입하는 업계 표준으로 채택이 확산되고 있습니다. 텍스트 Watermark 기술은 아직 표준화가 유동적이므로, 우선 HTTP Response Header나 구조화된 Data를 통한 명시부터 시작하는 것이 현실적입니다.

```typescript
// app/api/generate/route.ts
export async function POST(req: Request) {
  const result = await generateText({ /* ... */ });

  return Response.json(
    { content: result.text },
    {
      headers: {
        "X-AI-Generated": "true",
        "X-AI-Generator": "webhani-assistant/1.0",
      },
    }
  );
}
```

향후 C2PA 등의 Provenance 표준 대응이 요구될 가능성이 높으므로, 생성 Pipeline 설계 단계에서 Metadata 삽입을 위한 확장 지점을 미리 마련해두면 이후 대응 비용을 줄일 수 있습니다.

## webhani의 견해

이런 종류의 규제는 "번거로운 Compliance 작업"으로 여겨지기 쉽지만, 실무적으로는 UI/UX 설계의 일부로 통합하는 것이 가장 효율적입니다. 공개 Label이나 Provenance Metadata를 나중에 추가하려고 하면 Component 구조와 API Response 형식을 전방위적으로 수정해야 하는 경우가 많습니다.

AI 기능을 포함한 신규 Project에서는 설계 초기 단계부터 "AI와의 상호작용 공개"와 "생성 Content Marking"을 Component의 표준 사양으로 포함시킬 것을 권장합니다. EU 권역 외 Service라 하더라도 유사한 규제가 다른 지역으로 확산되는 추세이므로, 선제적으로 설계해두는 것이 장기적으로 비용을 절감합니다.

## 정리

- EU AI Act 제50조는 2026년 8월 2일부터 시행 중이며, 고위험 System에 국한되지 않음
- Chatbot·AI Agent는 "AI와 대화 중"임을 공개해야 함
- AI 생성 Content는 기계 판독 가능한 Marking이 필요 (기존 System은 2026년 12월 2일까지 유예)
- 공개 UI와 Provenance Metadata는 사후 추가가 아니라 설계 단계부터 반영하는 것이 효율적

AI 기능 구현과 함께 이러한 규제 대응 설계에 대한 상담도 진행하고 있습니다.
