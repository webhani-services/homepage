2026년 11월 4일 Kubernetes v1.38.0-beta.0이 릴리스되었습니다. 공식 릴리스 일정에 따르면 Deprecation·Removal 관련 블로그 글은 11월 23일, GA는 12월 16일로 예정되어 있습니다. 이번 주에는 KubeCon + CloudNativeCon North America가 열리고 있어 1.38 이야기가 많이 나오겠지만, 대부분은 새 기능에 관한 내용일 것입니다.

운영 관점에서 Upgrade를 깨뜨리는 것은 새 기능이 아닙니다. 더 이상 존재하지 않는 것을 참조하는 Configuration입니다. 1.38에서는 주로 **제거된 Feature Gate**와 **제거가 연기되었던 kubelet Flag**가 여기에 해당합니다. 이런 것들을 찾기에는 Beta 기간이 가장 좋은 시점입니다.

## 지금까지 알려진 내용

최종 목록은 아직 확정되지 않았고, 공개 정보 대부분은 Alpha Changelog와 Beta 이전의 Preview 글에서 나온 것입니다. 이를 전제로 Upgrade 계획과 관련된 항목을 정리합니다.

**제거·고정되는 항목**

- `KubeletTracing`이 제거되었습니다. v1.34부터 GA로 켜진 상태에 고정되어 있던 Gate입니다.
- `DRADeviceTaints`와 `DRADeviceTaintRules`는 GA로 고정되어 더 이상 끌 수 없습니다.
- Sidero Labs의 `go-kubernetes` Library PR은 1.38.0-beta.0 기준으로 제거된 Feature Gate 19개를 Upgrade 검사에 추가했습니다. 이 중 `WinDSR`과 `WinOverlay`는 kube-proxy Gate라서 해당 Checker의 검사 대상이 아니라고 명시되어 있습니다.
- kubelet의 Container Runtime 관련 설정 Flag 일부는 원래 1.37에서 제거될 예정이었지만, containerd v1.7 호환을 위해 1.38로 연기되었습니다.

**눈여겨볼 승격 항목**

- `ShardedListAndWatch`가 Beta로 승격
- Windows CPU·Memory affinity가 Beta가 되어 기본 활성화
- `KubeProxyNFTablesLocalhostNodePorts`가 Beta가 되어 기본 활성화
- emptyDir Mode 제어, Volume 단위 기본 소유자 설정, bind mount 옵션 같은 Storage 기능과 DRA 속성 관련 기능이 Beta를 목표로 하고 있습니다

제3자 Preview에서는 추적 중인 Enhancement를 86~87건 정도로 보지만, 출처마다 숫자가 다릅니다. 건수는 참고용으로만 보십시오.

## 제거된 Gate가 왜 문제인가

기능이 GA가 되면 해당 Gate는 몇 릴리스 동안 `true`로 고정된 뒤 제거됩니다. Configuration에서 그 Gate를 명시적으로 지정해 둔 상태라면 (설령 `true`라도) Gate가 사라지는 순간 Component는 "unrecognized feature gate" 같은 오류를 내며 기동을 거부합니다.

이런 설정은 잘 돌아가는 구성을 아무도 건드리지 않기 때문에 몇 년씩 남아 있곤 합니다. kubeadm Configuration, kubelet 설정 파일, Helm values, Managed Cluster용 Terraform Module, CI에서 쓰는 `kind` 설정 같은 곳에 숨어 있습니다.

## Step 1: 명시적 Feature Gate 찾기

먼저 Infrastructure Repository부터 찾아봅니다.

```bash
# IaC와 Manifest 안의 명시적 Feature Gate 설정을 모두 검색
grep -rnE --include='*.yaml' --include='*.yml' --include='*.tf' \
  --include='*.json' --include='*.toml' \
  'feature-gates|featureGates|feature_gates' .
```

다음으로, 운영 중인 Cluster에서 실제로 무엇이 켜져 있는지 확인합니다. API Server와 kubelet은 `kubernetes_feature_enabled` Metric을 제공합니다.

```bash
# API Server 기준
kubectl get --raw /metrics | grep '^kubernetes_feature_enabled' \
  | grep -E 'KubeletTracing|DRADeviceTaint|WinDSR|WinOverlay'

# 특정 Node의 kubelet 기준
NODE=$(kubectl get nodes -o jsonpath='{.items[0].metadata.name}')
kubectl get --raw "/api/v1/nodes/${NODE}/proxy/metrics" \
  | grep '^kubernetes_feature_enabled'
```

이 Metric은 "켜져 있는지"를 보여줄 뿐 "명시적으로 설정되었는지"는 알려주지 않습니다. grep 결과와 함께 보고 삭제해야 할 명시적 참조를 찾으십시오.

## Step 2: 제거 목록과 대조하기

공식 1.38 Changelog와 11월 23일 블로그 글이 나오면, 제거된 Gate 목록을 CI에서 돌릴 수 있는 검사로 바꿉니다.

```bash
#!/usr/bin/env bash
# check-removed-gates.sh — 1.38에서 제거된 Gate를 참조하면 실패
set -euo pipefail

# 공식 CHANGELOG-1.38 공개 후 채우기
REMOVED_GATES=(
  KubeletTracing
  # ...
)

status=0
for gate in "${REMOVED_GATES[@]}"; do
  if grep -rnw --include='*.yaml' --include='*.yml' --include='*.tf' \
       --include='*.json' --include='*.toml' "${gate}" infra/; then
    echo "::error::Removed feature gate referenced: ${gate}"
    status=1
  fi
done
exit $status
```

일부러 단순하게 만들었습니다. 핵심은 검사를 반복 가능하게 만드는 것이고, 다음 Minor Upgrade 때는 목록만 바꿔서 재사용할 수 있습니다.

## Step 3: kubelet Runtime Flag와 containerd 버전 확인

연기되었던 kubelet Flag 제거의 영향을 가장 크게 받는 것은 아직 containerd 1.7을 쓰는 Cluster입니다. 각 Node가 보고하는 값을 확인합니다.

```bash
kubectl get nodes \
  -o custom-columns='NODE:.metadata.name,RUNTIME:.status.nodeInfo.containerRuntimeVersion,KUBELET:.status.nodeInfo.kubeletVersion'
```

`containerd://1.7.x`가 남아 있다면, 1.38 Upgrade와는 별개의 변경으로 containerd 2.x 이전을 먼저 계획하십시오. Runtime Major 버전 변경과 Kubernetes Minor Upgrade를 같은 Maintenance 창에 묶으면 장애 원인 분리가 훨씬 어려워집니다.

## Step 4: Beta에서 Workload 실행하기

Beta 릴리스는 바로 이런 용도입니다. 1.38 Beta로 일회용 Cluster를 띄우고 (kind, 또는 Provider가 Preview Channel을 제공한다면 비운영 Cluster), Manifest와 Helm Chart를 적용한 뒤 기존 Smoke Test를 돌립니다.

그동안 Deprecated API 사용 현황도 확인해 둡니다.

```bash
kubectl get --raw /metrics | grep '^apiserver_requested_deprecated_apis'
```

여기에 나타나는 것은 향후 릴리스에서 제거가 예정된 것들입니다.

## Managed Kubernetes 일정

EKS, GKE, AKS를 쓴다면 12월 16일에 1.38을 바로 쓸 수는 없습니다. Managed Service는 보통 upstream보다 몇 주에서 몇 달 늦게 따라옵니다. 그래도 Beta를 확인할 가치는 있습니다. 제거되는 Gate와 Flag는 동일하므로, 지금 Configuration을 고쳐 두면 Managed Upgrade가 왔을 때 아무 일도 일어나지 않습니다.

## webhani의 관점

Kubernetes Upgrade 프로젝트에서 저희는 거의 매번 같은 패턴을 봅니다. Cluster 자체는 문제없이 올라가고, 오래된 Feature Gate나 예전 Runtime Flag, 잊힌 Helm Chart 속 Deprecated API 같은 작은 것이 장애를 일으킵니다. 어느 것도 고치는 데 깊은 Kubernetes 지식이 필요하지 않습니다. 필요한 것은 Upgrade 후가 아니라 전에 누군가 확인하는 것입니다.

앞으로 6주 동안 권장하는 작업은 다음과 같습니다.

- IaC grep과 Live Metric을 함께 사용해 명시적 Feature Gate를 지금 점검
- 11월 23일 Removal 글이 나오면 CI 검사로 변환
- containerd 1.7 → 2.x 이전은 Kubernetes Upgrade와 분리
- hello-world Pod가 아니라 실제 Workload를 Beta에서 실행
- Script는 남겨 두기. 다음 Upgrade에서도 다시 쓰게 됩니다
